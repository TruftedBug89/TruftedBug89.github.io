## 2024-05-09 - Session Tokens in Local-Only Apps
**Vulnerability:** Session identifiers were stored in `document.cookie` in a strictly local, serverless application.
**Learning:** Even without a backend, browsers automatically attach cookies to network requests (e.g., when fetching static assets from GitHub Pages or third-party APIs). This inadvertently leaks session tokens. Standard cookie protections like `SameSite=Lax` and `Secure` are misapplied here, as they secure client-server communication, which doesn't exist in this architecture.
**Prevention:** For local-first applications where privacy from servers is paramount, strictly use `localStorage` for all sensitive identifiers, user data, and API keys to prevent automated browser transmission. Add explanatory comments to prevent future developers from mistakenly "securing" it back into a cookie.

## 2024-05-28 - DOM XSS in Toast Notifications
**Vulnerability:** XSS (Cross-Site Scripting) vulnerability in `components/network-status.js`. The `_showToast` function injected dynamically created messages directly into the DOM using `this.toast.innerHTML`.
**Learning:** Even internal utility functions like toast notifications must treat all inputs as potentially untrusted or malicious, especially in a localized app where network responses or imported data may eventually feed into them.
**Prevention:** Always use `textContent` instead of `innerHTML` when displaying plain text to completely prevent DOM-based XSS, as it treats all input strictly as text, neutralizing any HTML tags.

## 2024-07-26 - DOM XSS in InnerHTML Templates
**Vulnerability:** XSS (Cross-Site Scripting) vulnerability in `js/tone-practice.js` and potentially others. The template string injected dynamically created quiz data (`q.question`, `q.pinyin`) directly into the DOM using `innerHTML` without escaping.
**Learning:** In a vanilla JS SPA that relies on `innerHTML` for templating, it's very easy to miss escaping variables, creating DOM XSS sinks, especially when the data source isn't immediately obvious as "user input" (e.g., loaded from a local JSON file or generated by a function).
**Prevention:** Whenever generating HTML strings that will be assigned to `innerHTML`, aggressively wrap any dynamic variable interpolation with `Utils.escapeHtml()`. Alternatively, use safer DOM manipulation methods like `document.createElement()` and `textContent` for dynamic values.
## 2024-05-24 - Unsanitized Mission Data in Animation
**Vulnerability:** DOM-based Cross-Site Scripting (XSS) in `js/animations.js`. Mission properties (`mission.icon`, `mission.reward`) were directly concatenated into an HTML template string assigned to `overlay.innerHTML`.
**Learning:** Even though missions might seem like internal application state, if they are ever loaded from external sources, local storage, or modified via other means, they become an XSS vector when injected dynamically.
**Prevention:** Always sanitize any dynamic variables interpolated into `innerHTML` strings using `Utils.escapeHtml()`, especially when the data originates from objects that could potentially be tampered with.
